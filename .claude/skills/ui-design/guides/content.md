# 界面文案与信息密度

界面文案（UI copy）服务于操作与理解。标题、操作名称、真实状态、选项含义和必要帮助应当简短明确；每段文字都要提供界面结构尚未表达的信息。

- 删除空泛口号和装饰性文案，如“轻松整理，顺手连接”“每一步，都有明确回应”。
- 删除重复介绍页面用途的辅助文案，如设置页中的“常用选项集中在这里，随时可以调整”。
- 应用名称、页面标题与分组标题按导航层级使用，同一区域不重复放多个同义标题。
- 提示说明实际结果或必要下一步，不用泛泛说明替代控件的真实动作。
- 空状态说明缺少什么，并提供对应操作；选项副标题只补充名称无法说明的含义。
- 必要说明放在对应操作附近；按需帮助使用 Tooltip、帮助入口或展开说明。
- 失败提示保留实际原因与必要恢复动作。新增或修改界面文案时，按 translation 技能查阅词典和资源键指南。

## 操作结果与常驻说明

界面操作的成功、错误等动态结果一律使用 Toast；静态常驻说明在对应界面显示。Toast 使用短小浮层，按组件规范自动消失，可提供手动关闭；不把操作结果做成永久提示栏。

2类文案都用简短直接的句子，只表达真实结果、当前条件或必要限制。详细帮助按需展开，不把解释、操作介绍或诊断堆栈塞进提示。业务数据与设置值正常更新，不用 Toast 替代它们的持续显示。

| 文案 | 处理 |
|---|---|
| “按你的习惯来” | 使用“应用设置”等明确页面名称 |
| “你可以在应用设置中调整连接选项” | 导航控件直接进入对应设置，不用提示代替导航 |
| “连接完成时提醒我” | 保留，解释通知开关的具体行为 |
| “尚无设备”与“连接设备” | 保留，表达真实空状态及操作 |

“装饰性文案”指没有操作信息的口号或点缀文字；“冗余辅助文案”指重复标题、布局或控件已表达的信息。按内容作用判断，不按字数删除必要说明。
