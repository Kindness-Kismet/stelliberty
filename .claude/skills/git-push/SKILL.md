# Git 推送

先阅读根目录 `AGENTS.md`，核对实际仓库、远端、来源与目标引用。需要准备提交或整理历史时，阅读同级 `../commit/SKILL.md`；本技能负责推送范围、用户确认、次数与远端结果。

用户提出推送请求后，先准备具体推送内容，再按下述规则询问执行许可。

## 执行流程

1. 检查当前分支、HEAD、工作区、暂存区与实际远端配置，确定待推送的仓库、提交、来源引用和目标引用。本地提交准备按 commit skill 完成，工作区其余改动保留原状。
2. 更新相关远端引用，比较待推送提交与远端状态，核对实际差异、必要验证、隐私检查和引用关系。读取远端配置时对凭据及私人地址作脱敏展示。
3. 向用户展示仓库、远端名称、来源到目标的指向、待推送提交与简要改动、拟执行命令，以及适用的剩余授权次数。
4. 默认询问“是否允许执行这1次推送？”，获得明确答复后执行。已有精确次数授权且剩余次数覆盖本次范围时，直接使用剩余额度；额度用完或本次范围需要扩展时，再展示实际内容并询问。
5. 执行前复核提交 SHA、目标引用和命令参数符合授权，记录本次调用与授权余额，再执行使用明确 refspec 的推送。
6. 查询远端引用和实际返回结果，记录已消耗次数、剩余次数与推送结果；失败时按实际原因处理后续，重试继续遵循次数规则。

## 许可与次数

- 默认同意授权1次实际推送调用。例如用户回复“可以”“允许推送”，授权次数记为1。
- 用户精确说明次数时，按其允许的有限正整数记录。例如“允许接下来3次推送”授权3次，在对应范围内依次使用。
- 1次以实际启动的 `git push` 调用计数。成功、失败、远端已是最新状态以及结果暂时无法确认的调用，均消耗1次；失败后的重试计为新的1次。
- 包装脚本或其他工具产生的实际 Git 推送按相同规则逐次计数。单次调用包含多个引用时，全部目标引用都纳入该次确认范围。
- 调用包装工具前核对其隐式推送与自动重试行为，采用每次启动前都能核对额度的执行方式；创建 PR 等后续操作优先复用已经完成的显式推送。
- 授权记录包含用户原话、允许次数、实际仓库、远端、目标引用、任务范围、已消耗次数与剩余次数。会话内跨轮次和上下文压缩继续核对同一份记录。
- 同一授权由当前主 agent 维护余额，推送按顺序执行；委派调用前先预占1次额度，命令已启动后记为消耗，工具明确在启动前拒绝时释放该次预占。
- 明确的多次授权覆盖约定任务范围内后续提交；仓库、远端、目标引用或推送方式发生范围外变化时，展示差异并取得对应许可。
- 强制更新、删除远端引用和新增推送目标在许可范围中明确列出。用户撤销许可后结束该授权；新会话依据当次用户确认建立授权记录。
- 次数或范围存在歧义时先澄清。工具明确在命令启动前拒绝执行时，该调用保持未消耗；命令已启动且结果待确认时，保留已消耗状态并查询远端。

需要确认时，说明本技能的要求：**“默认同意只授权1次推送；明确允许 N 次时按剩余次数执行。”** 当前有效许可已覆盖的操作直接执行。

## 结果核对

- 普通分支推送核对远端目标是否达到预期提交，标签推送核对目标标签对应的对象与提交；按实际结果报告。
- 网络中断或返回结果待确认时，先查询远端引用，再决定是否需要重试。每次已启动的调用都保留在次数记录中。
- 远端拒绝更新时先核对最新远端状态和拒绝原因，再按任务范围准备修正；涉及提交历史调整时按 commit skill 执行。
- 明确授权强制更新时，结合已核对的远端提交使用带预期值的 lease 约束，执行前再次核对许可范围。

## 完成与维护

报告实际推送的仓库、远端、目标引用、提交结果、本次消耗次数和剩余次数。剩余额度用于会话内已约定范围的后续推送，默认1次许可在本次调用后用完。
