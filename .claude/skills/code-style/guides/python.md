# Python 代码风格

## 命名

| 标识符 | 写法 | 示例 |
|---|---|---|
| 模块、函数、方法、参数、局部变量、属性 | snake_case | `archive_io`、`read_entry`、`entry_count` |
| 类与异常类型 | CapWords，异常通常以 Error 结尾 | `ArchiveEntry`、`ArchiveReadError` |
| 模块级常量 | 大写下划线 | `MAX_ENTRIES` |
| 非公开成员 | 单下划线前缀 | `_buffer_size` |

布尔查询使用 `is_empty`、`has_entries`，普通状态可用 `enabled`。实例方法首参为 `self`，类方法为 `cls`；异步函数按动作命名。双端下划线名称用于语言协议。

- 关键字冲突可加尾部下划线，如 `class_`；双前导下划线具有名字改写语义，普通内部成员通常用单下划线。
- 参数、dataclass 字段可能参与关键字调用、模式匹配与序列化，重命名要追踪契约。
- 集合参数可用 `entries`，数量用 `entry_count`；术语缩写按语言写作 `HTTPError`、`parse_http_header`。

## 导入与包

- 导入、缩进与格式沿用项目生效的 PEP 8 和 formatter 配置；常规顺序为模块文档字符串、`__future__`、标准库、第三方、本地模块，组间空行。
- 项目要求入口先设置缓存或运行环境时，设置放在 `__future__` 之后、本地模块导入之前；实际开关和子进程继承由工程入口维护。
- 不使用 `from module import *`；别名说明真实角色。绝对导入或包内相对导入按项目加载方式选择，避免依赖当前工作目录。
- 延迟导入用于真实的可选依赖或初始化需求，不用于掩盖错误的循环依赖；类型专用导入可在适用时使用 `TYPE_CHECKING`。
- 目录优先采用实际加载器支持的命名空间包；`__init__.py` 只为初始化、导出接口或加载器要求创建，清理纯占位空文件。归档分发核对实际包发现与目录收纳。

## 类型与控制流

- 类型注解表达实际接口和缺项语义，采用当前解释器支持的语法；不为内部已成立的类型重复运行时检查。
- 默认参数避免共享可变对象；区分 `None` 与空值、零值，不能用真值判断覆盖有效业务输入。
- 迭代和推导式保持清晰，复杂副作用使用普通循环；对象状态和模块级可变状态归属明确。

## 错误、资源与异步

- 捕获具体且本层可处理的异常，转换异常时使用 `raise ... from error` 保留原因；不使用裸 `except` 吞掉退出与中断。
- 文件、锁和连接采用 `with` 或 `async with` 管理；清理放在明确的作用域或 `finally`，保持原始失败可见。
- 异步操作使用实际异步 API，阻塞工作按项目方式移出事件循环；任务必须有等待、取消与异常观察路径。
- 取消和退出沿调用链传播，平台、IO、UI 调度位于实际边界，不混入纯模型。

## 格式与验证

沿用项目已有 formatter、lint、类型检查和执行入口；包与导入变更要从实际启动目录及打包方式核对。
