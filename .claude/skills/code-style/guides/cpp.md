# C++ 代码风格

## 命名

| 标识符 | 项目没有既定规则时 | 示例 |
|---|---|---|
| 类型、类型别名、概念与类型模板参数 | PascalCase | `ArchiveEntry`、`EntryType` |
| 函数、方法、参数、变量、命名空间 | snake_case | `read_entry`、`entry_count`、`archive` |
| 常量、必要的宏 | 大写下划线，公共宏加项目前缀 | `MAX_ENTRIES`、`ARCHIVE_HAS_ZSTD` |
| 布尔值或查询方法 | 表达状态、能力或条件 | `is_empty`、`can_read` |

私有字段后缀、枚举项和常量写法跟随已有约定及 clang-tidy 配置。重载、虚函数重写和对外符号沿用声明名称。

- 作用域枚举连同类型阅读，如 `OpenMode::ReadOnly`；公共宏使用项目独有前缀。
- 所有者和借用者由类型表达，名称区分角色，如 `source`、`destination`。
- 标准协议沿用 `begin()`、`end()`、`value_type` 等要求的拼写；C 语言链接保留既有 ABI 符号。

## 包含与命名空间

- 源文件先包含对应头文件，再按项目配置排列标准库、第三方与本项目头文件；直接包含实际使用的声明，不依赖传递包含。
- 头文件可独立包含，使用项目已有的 include guard 或 `#pragma once`。前置声明仅用于不需要完整类型的真实边界。
- 头文件不写全局 `using namespace`；实现中使用限定名或局部 `using` 声明，缩短作用域并保持来源清楚。
- 内部实现留在私有成员、源文件或匿名命名空间；模块和条件编译沿用实际标准、工具链及平台边界。

## 类型与所有权

- 使用 RAII 管理内存、文件和锁；独占所有权优先 `unique_ptr`，确有共同拥有时才用 `shared_ptr`。
- 裸指针和引用表达非拥有访问，明确可空性及生命周期；借用不能越过拥有者的生命周期。
- 根据类型和使用处选择 `auto`，避免隐藏有影响的转换；用 `const`、引用与值语义表达修改和所有权需求。
- 可用时采用作用域枚举、`constexpr`、标准容器和算法；不以宏代替类型系统或普通函数。窄化与布局转换在边界显式处理。

## 错误与并发

- 沿用项目的异常、状态码或结果类型，保留失败上下文；不使用 catch-all 吞错。解构与清理路径遵守不抛异常的契约。
- 跨 ABI 的分配释放、布局、编码、错误、取消与生命周期由包装边界统一处理；异常不越过不支持它的边界。
- 使用作用域锁，缩短临界区；共享状态和任务生命周期明确，不在持锁时执行无关阻塞操作或外部回调。
- 异步与 UI 调度按实际框架执行，模型不直接依赖窗口或平台 IO。

## 格式与验证

沿用实际 C++ 标准、clang-format、clang-tidy 和构建配置；公共头及模板变化按受影响消费者验证。
