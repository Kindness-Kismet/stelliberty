# Go 代码风格

## 命名

| 标识符 | 写法 | 示例 |
|---|---|---|
| 包名 | 小写短词，调用处连同包名阅读 | `archive.Reader` |
| 导出类型、函数、字段、常量 | 大写字母开头，多个词用 MixedCaps | `Reader`、`ReadEntry`、`MaxEntries` |
| 包内标识符、参数、变量 | 小写字母开头，多个词用 mixedCaps | `readEntry`、`entryCount` |
| 常见缩写 | 保持一致大小写 | `HTTPClient`、`userID`、`urlPath` |

接收者使用类型短名，如 `func (r *Reader) Read(...)`，同一类型保持一致。getter 可直接叫 `Name()`；布尔值也可用 `ok`、`found`、`enabled`。修改首字母时核对导出范围。

- 单方法接口通常由方法名派生，如 `Reader`、`Stringer`，优先复用标准库契约。
- 局部错误使用 `err`，哨兵错误可用 `ErrNotFound`，错误类型可用 `ParseError`。
- 构造函数连同包名阅读，如 `archive.NewReader`；已有测试文件与函数沿用 `reader_test.go`、`TestReadEntry`。

## 导入与包

- 标准库与外部、当前模块依赖分组，排序交给 gofmt 或项目已有导入工具；冲突时使用明确包别名。
- 不使用 dot import 隐藏来源；空白导入仅用于实际驱动注册等副作用，并让注册意图可见。
- 包按职责组织，避免循环依赖和含义宽泛的 `utils` 包；接口通常定义在消费者边界，不为每个具体类型机械建立接口。

## 类型与错误

- 优先使用有意义的零值，区分 nil、空集合和缺项的业务语义；不为零值可直接使用的类型编造初始化要求。
- 错误作为返回值处理，增加上下文时使用 `%w` 保留链；按契约使用 `errors.Is`、`errors.As`，不匹配错误字符串。
- 常规失败不用 `panic`，`recover` 只用于确有隔离职责的边界；结果与错误语义保持一致。
- 接口值注意动态类型与 typed nil 的区别；避免向调用方返回携带 nil 指针的非 nil 错误接口。

## 资源与并发

- 成功取得资源后安排 `defer` 释放；循环内资源生命周期过长时缩短作用域，写入完成所依赖的 Close 错误按契约处理。
- goroutine 必须有结束条件与所有者，沿调用链传递 `context.Context`，通常作为首个参数；不把请求上下文存入长期对象。
- 发送方或明确拥有者负责关闭 channel；共享状态用锁、channel 或原子操作同步，不以无约束 goroutine 掩盖阻塞。
- 含锁对象不随意复制，临界区只覆盖共享状态；取消后仍需收尾并观察已启动任务。

## 格式与验证

使用 gofmt 和项目已有的构建、vet、lint 或测试入口；并发修改按实际风险使用已有 race 检查，避免无关全仓验证。
