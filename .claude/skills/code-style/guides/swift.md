# Swift 代码风格

## 命名

- 类型、协议和泛型参数用 UpperCamelCase；函数、属性、变量、枚举 case 用 lowerCamelCase。
- 名称在调用处表达清楚，参数标签说明角色；布尔值用 `isEmpty`、`hasEntries`，转换按实际行为命名。
- 缩写沿用 Swift API 约定与项目惯例，如 `URL`、`URLSession`；协议实现、ObjC 选择器和序列化键保持真实契约。

## 导入与模块

- `import` 放在文件顶部，按项目 formatter 排序；只引入实际使用的模块，条件导入与调用采用匹配的 `#if` 条件。
- 类型名冲突时使用模块限定名；扩展按职责组织，避免借扩展让业务直接依赖平台实现。
- 采用最小必要访问级别，公共接口明确 ABI 与模块消费者；`@testable import` 仅用于实际测试目标。

## 类型与控制流

- 默认 `let`，需要修改时使用 `var`；优先以结构体、枚举等值类型表达纯模型，引用语义按真实身份与生命周期选择。
- 可选值使用 `if let`、`guard let`、可选链或模式匹配处理，不用强制解包掩盖未建立的不变量。
- 枚举采用穷尽分发，`guard` 用于真实前提；`try?` 仅在契约明确允许丢弃错误详情时使用，常规失败不使用 `try!`。

## 错误、资源与并发

- 使用 `throws` 与 `try` 沿调用链传播失败，转换错误保留操作上下文；只在能恢复或展示结果的边界捕获。
- 资源按所有者生命周期释放，必要清理用 `defer`；闭包捕获根据实际拥有关系选择，检查引用环，避免机械使用 weak 或 unowned。
- 优先结构化并发，非结构化 Task 必须有持有者、取消和失败观察路径；取消是协作式的，长任务在合适边界检查。
- actor、`Sendable` 与 `@MainActor` 按真实隔离边界使用，不用 unchecked 声明绕过未确认的线程安全；阻塞操作不占用 UI 执行上下文。

## 格式与验证

沿用实际 Swift 版本、并发检查模式、formatter 和构建入口；模块、隔离或 ObjC 互操作变化检查真实消费者。
