# JavaScript 代码风格

## 命名

- 类和构造器用 PascalCase；函数、方法、变量、属性用 camelCase；约定的模块级常量用 SCREAMING_SNAKE_CASE。
- 普通 `const` 绑定仍按内容命名，如 `entryCount`。布尔值用 `isReady`、`hasEntries`，回调按事件命名，如 `onEntryRead`。
- 文件名遵循当前模块约定；外部 JSON、URL 和序列化字段保持协议拼写，在边界映射到内部名称。

## 导入与模块

- 使用项目已配置的 ESM 或 CommonJS，导入放在模块顶部；命名导入和别名明确来源，扩展名和路径与真实运行环境一致。
- 命名空间导入适用于整体使用一个模块 API 的场景；聚合入口仅暴露稳定接口，避免宽泛重导出与循环依赖。
- 副作用导入、动态 `import()` 和条件加载要有真实的初始化、可选依赖或按需加载需求。
- 模块按职责拆分，避免依赖全局变量或隐含执行顺序；浏览器、Node 和其他宿主能力留在实际边界。

## 值与状态

- 优先 `const`，需要重新赋值时用 `let`；新代码不使用 `var`。默认采用严格相等，类型转换在边界显式完成。
- `null`、`undefined`、空字符串和零值按真实语义区分；默认值允许零或空字符串时使用相应的空值处理，不机械使用 `||`。
- 对象形状和公共参数保持稳定；只有真实未知输入才做结构校验，不在内部反复猜测类型。
- 状态由明确的所有者更新，使用展开或拷贝时理解其浅拷贝语义；不通过直接修改共享对象绕过实际状态流程。

## 错误与异步

- 抛出 `Error` 或项目定义的错误类型，保留原因与操作上下文；`catch` 只处理能恢复或转换的失败。
- 异步任务被等待或有明确的异常观察路径；不在 `forEach` 中用异步回调期待整组等待。
- 独立操作可用实际需要的并发组合，有先后关系或共享状态的操作顺序执行；根据业务选择失败立即结束或收集结果。
- 取消和超时使用宿主支持的信号机制；监听器、定时器、连接等随所有者清理，避免任务结束后继续更新失效状态。

## 格式与验证

采用项目已有 formatter、lint 与运行入口；必要类型约定沿用已有 JSDoc，不为代码风格任务切换语言或模块制式。
