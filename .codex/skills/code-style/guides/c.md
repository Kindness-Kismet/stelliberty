# C 代码风格

## 命名

| 标识符 | 新代码建议 | 示例 |
|---|---|---|
| 函数 | 小写下划线，对外函数带库或模块前缀 | `archive_open`、`archive_is_empty` |
| 参数、局部变量、结构体成员 | 小写下划线 | `entry_count`、`buffer_size` |
| 结构体、枚举类型和类型别名 | 沿用项目的类型命名，缺省可用小写下划线 | `struct archive_entry` |
| 宏与枚举常量 | 大写下划线，公共名称带项目前缀 | `ARCHIVE_MAX_ENTRIES`、`ARCHIVE_READ_ONLY` |

文件作用域标识符、宏和枚举常量都需要考虑名字冲突。对外符号统一使用项目短前缀，内部链接的辅助函数可省略。避开实现保留的标识符，面向 POSIX 的新类型别名也避开保留的 `_t` 后缀。

- 容量和长度分开命名，如 `buffer_capacity` 与 `bytes_written`；输出指针表达值与单位，如 `size_t *bytes_read`。
- 函数指针类型按用途命名，如 `archive_visit_fn`；回调参数可用 `visit` 与 `user_data`。
- 头文件保护宏由项目、路径和文件名组成，如 `ARCHIVE_IO_READER_H`。

## 包含与模块

- 源文件先包含对应头文件，再按项目约定分组包含标准库、第三方与项目头文件；直接包含实际使用声明的头，不依赖传递包含。
- 头文件保持可独立包含，使用 include guard；已有工程明确采用 `#pragma once` 时沿用。公开头只暴露契约所需类型和声明。
- 内部函数与文件级状态使用 `static` 限定链接范围；函数声明明确参数类型，无参数函数按目标标准使用 `(void)`。
- 平台条件编译集中在实际平台边界；声明、包含与实现采用匹配条件，避免把平台宏扩散到纯业务。

## 类型与控制流

- 长度和容量采用与库契约一致的类型，通常为 `size_t`；固定宽度类型用于协议或布局确有位宽要求的字段。
- 核对有符号/无符号转换和窄化；分配大小计算在真实输入边界检查溢出，不能只检查分配结果。
- 指针与长度、容量的关系明确；只读借用使用 `const`，字符串接口明确终止符与可写空间。
- 宏仅用于编译期或预处理需求，避免重复求值和隐含副作用；普通逻辑优先函数或目标标准支持的 `static inline`。

## 错误与资源

- 失败通过明确状态码和输出参数契约返回，检查可能失败的分配、IO 和系统调用；保留错误上下文与需要的原始错误码。
- 明确内存与句柄由谁创建、转移和释放；所有退出路径释放已取得资源，多资源函数可用单一清理标签按取得的逆序释放。
- `realloc` 先接收临时结果，成功后再更新拥有指针，避免失败时丢失原分配。
- 不以返回零值或重复判空隐藏错误；跨线程共享状态采用目标标准和平台支持的原子或锁，`volatile` 不充当同步机制。

## 格式与验证

沿用实际 C 标准、formatter、编译警告和静态检查入口；修改头文件后核对真实消费者与 ABI。
