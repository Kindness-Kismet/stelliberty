# Java 代码风格

## 命名

- 包名使用小写分段；类、接口、枚举和类型参数用 UpperCamelCase，短类型参数可用 `T`、`K`、`V`。
- 方法、参数、变量和字段用 lowerCamelCase；常量用 UPPER_SNAKE_CASE。
- 布尔查询用 `isEmpty`、`hasEntries`；异常类型以 `Exception` 结尾。重写、JavaBeans、反射和序列化成员遵循实际契约。

## 导入与包

- 包声明之后显式导入实际依赖，不使用通配导入；普通导入和静态导入按项目 formatter 分组与排序。
- 静态导入只用于来源清楚的常量或操作；同名类型冲突时保留一个导入，另一个使用限定名。
- 公开类型与文件名匹配，包按职责组织；优先最小必要可见性，包级实现不因方便访问全部设为 public。

## 类型与控制流

- 泛型表达实际类型关系，避免原始类型与未核对的强制转换；`var` 只在目标版本支持且类型清楚时使用。
- 可变状态保持局部，`final`、不可变集合或 record 按实际版本和契约选择；明确集合视图、浅拷贝和真正独立数据的区别。
- 缺项语义保持一致，按现有 API 使用空值、Optional 或结果类型，不在同一接口混用多套约定。
- 枚举和状态类型采用明确分发，卫语句处理真实前提；对象比较按语义使用 `equals` 或适当工具，不用 `==` 比较值对象。

## 异常、资源与并发

- 捕获具体且可处理的异常，转换时保留 cause；不捕获 `Throwable` 掩盖严重运行时失败。
- 可关闭资源使用 try-with-resources，明确资源所有者；跨边界传递的资源不能被局部作用域提前关闭。
- `InterruptedException` 沿接口传播；确需转换且无法继续抛出时恢复线程中断标记，不吞掉取消信号。
- 异步任务由明确的 executor 或宿主持有，观察 Future/CompletionStage 的失败并按生命周期取消；共享状态使用实际锁或并发容器。

## 格式与验证

沿用项目的 Java 版本、formatter、静态检查与 Maven/Gradle 入口；新增语法与并发 API 必须符合实际运行版本。
